# Конспект аналізу ТЗ проєкту Student Assistant

## Функціональні вимоги
- Додавання нових навчальних завдань
- Перегляд списку всіх завдань
- Відмітка завдань як виконаних/невиконаних
- Встановлення пріоритету завдань (low, medium, high)
- Встановлення терміну виконання (dueDate)
- Збереження даних у форматі JSON

## Нефункціональні вимоги
- Кросплатформність: підтримка Windows, macOS, Linux
- Гетерогенна архітектура: різні клієнти з однієї технології
- Спільний формат обміну даними між усіма клієнтами
- Зручність використання інтерфейсу
- Відсутність залежності від серверної частини (локальне збереження)

## Модулі та технології
| Модуль | Технологія | Призначення |
|--------|-----------|-------------|
| frontend/ | React | Веб-інтерфейс |
| desktop-container/ | Electron/NW.js | Десктопна обгортка веб-інтерфейсу |
| cpp-core/ | C++/Qt | Нативний десктопний клієнт |
| python-analytics/ | Python/Flet | Аналітична панель з графіками |
| data/ | JSON | Спільний файл обміну даними |

## Формат обміну даними
Файл `data/tasks.json` містить масив об'єктів завдань:
```json
{
  "id": number,           // Унікальний ідентифікатор
  "title": string,        // Назва завдання
  "completed": boolean,   // Статус виконання
  "dueDate": string,      // Термін виконання (YYYY-MM-DD)
  "priority": string      // Пріоритет (low/medium/high)
}
```

## Відкриті питання
- Чи потрібна синхронізація між клієнтами в реальному часі?
- Як вирішувати конфлікти при одночасній роботі кількох клієнтів?
- Чи потрібна підтримка категорій/тегів для завдань?
- Чи планується експорт/імпорт даних в інших форматах?
- Який максимальний обсяг даних (кількість завдань) має підтримуватися?
